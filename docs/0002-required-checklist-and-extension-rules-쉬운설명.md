# B3-1 필수 요구사항과 확장 기준 (쉬운 설명판)

[과제 요구사항 요약](0051-requirements-and-review-reference.md) · [교육 목표](0004-educational-goals-and-learning-scope-쉬운설명.md) (원문: [0004-educational-goals-and-learning-scope.md](0004-educational-goals-and-learning-scope.md))

> 공식 요구사항 곳곳에 흩어져 있는 조건들을 학습자가 알기 쉽게 다시 분류하고 해석한 점검표입니다. 별도의 기관 세부 평가표는 아직 확인되지 않았습니다. 현재 실제로 실습을 진행하여 완료한 상태가 아니므로, 아래 점검표의 모든 체크박스는 미완료(`[ ]`) 상태로 유지하며 실습 수행이나 합격을 주장하지 않습니다.

---

## 1. 계정·리전·비용

- [ ] 실습은 아마존 웹 서비스(AWS, Amazon Web Services) 환경에서 진행한다.
- [ ] 모든 클라우드 자원은 대한민국 서울 리전(Region, 데이터센터가 있는 지역 거점인 `ap-northeast-2`)에 생성한다.
- [ ] 최고 관리자(Root) 계정 대신, 실습용으로 따로 만든 권한 관리 체계(IAM, Identity and Access Management) 사용자 또는 역할(Role)로 콘솔에 접근한다.
- [ ] 무료 이용 혜택 기준(프리 티어, Free Tier) 안에서 실습을 진행할 수 있는지 실제 내 계정의 남은 조건과 상태를 확인한다.
- [ ] 실습이 끝나면 생성했던 모든 클라우드 자원을 깔끔하게 정리(종료 및 삭제)한다.

> **주의:** 명세서에 '프리 티어'라고 적혀 있다고 해서 무조건 100% 무료가 보장되는 것은 아닙니다. 계정 가입 시기, 과거 사용 이력, 크레딧 보유 여부, 공인 IPv4 주소 요금 정책 등에 따라 요금이 나올 수 있으므로, 실제 자원을 만들기 전에 AWS 공식 요금 안내와 내 계정의 결제 대시보드를 직접 확인해야 합니다.

## 2. 네트워크 구성

- [ ] 독립된 가상 사설망(VPC, Virtual Private Cloud) 1개를 생성한다.
- [ ] 인터넷과 통신할 수 있는 공개 하위 네트워크 구역(Public Subnet) 1개를 생성한다.
- [ ] VPC와 바깥 인터넷을 연결해 주는 인터넷 출입구(Internet Gateway, IGW)를 생성하여 VPC에 연결한다.
- [ ] 해당 공개 서브넷이 사용하는 경로 안내표(Route Table, 라우트 테이블)에 모든 인터넷 세상(`0.0.0.0/0`)으로 나가는 길을 인터넷 게이트웨이(IGW)로 향하도록 등록한다.
- [ ] 가상 서버에서 바깥 인터넷으로 데이터 요청을 보내는 아웃바운드(Outbound, 나가는 통신)가 정상적으로 동작한다.

> **주의:** 명세 예시에 나오는 `curl <https://example.com>`의 꺾쇠괄호(`< >`)는 주소를 알아보기 쉽게 감싸둔 설명용 표기일 뿐입니다. 실제 리눅스 터미널 명령을 칠 때는 꺾쇠를 빼고 `curl https://example.com` 형태로 입력해야 합니다.

## 3. 가상 서버(EC2) 및 웹 서버 배포

- [ ] 공개 서브넷(Public Subnet) 안에 가상 서버(EC2 인스턴스) 1대를 생성한다.
- [ ] 내 컴퓨터 터미널에서 암호화 원격 접속(SSH, Secure Shell, 22번 포트)으로 가상 서버에 정상 접속할 수 있다.
- [ ] 가상 서버 안에 Nginx 같은 웹 서버 소프트웨어를 설치하고 정상 실행 상태로 유지한다.
- [ ] 가상 서버 내부에서 자기 자신에게 웹 요청을 보내는 명령(`curl http://localhost`)을 실행했을 때 정상 응답(HTTP 상태 코드 200)을 받는다.
- [ ] 외부 인터넷에서 접속해 검증할 수 있도록 공인 IP(Public IP)와 네트워크 통신 설정을 올바르게 갖춘다.

## 4. 접근 제어 (보안 그룹과 IAM 권한)

- [ ] 일반 웹 서비스 포트인 HTTP(80번 포트)는 전 세계 모든 곳(`0.0.0.0/0`)에서 접속할 수 있도록 허용한다.
- [ ] 관리자 원격 접속 포트인 SSH(22번 포트)는 보안을 위해 학습자 본인의 현재 인터넷 IP(또는 지정된 IP 대역)에서만 접속할 수 있도록 제한한다.
- [ ] 편의를 위해 모든 출입문 포트(0번부터 65535번까지)를 모든 사람(`0.0.0.0/0`)에게 통째로 열어두는 위험한 방화벽 규칙은 절대로 만들지 않는다.
- [ ] 실습용 IAM 사용자(또는 역할)의 권한은 이번 실습에 필요한 가상 서버(EC2), 가상 사설망(VPC), 보안 그룹(Security Group)의 생성·조회·태그·연결 작업 범위로만 철저히 제한한다.
- [ ] 모든 것을 다 할 수 있는 최고 관리자 권한(`AdministratorAccess`)은 절대로 부여하지 않는다.
- [ ] 이번 실습과 아무 관련 없는 클라우드 저장소(S3)나 데이터베이스(RDS) 같은 다른 서비스 관리 권한은 부여하지 않는다.

> **핵심 차이:** 가상 방화벽인 보안 그룹(Security Group)은 "어떤 IP와 포트의 네트워크 통신을 통과시킬 것인가"를 통제하고, 권한 관리 체계인 IAM은 "누가 AWS 클라우드 자원을 만들거나 지우는 관리 명령을 내릴 수 있는가"를 통제합니다. 둘은 완전히 다른 영역을 담당하므로 서로 대체할 수 없습니다.

## 5. 외부 접속 증명 (A 또는 B 중 하나 선택)

- [ ] **방식 A:** 외부 인터넷 웹 브라우저 주소창에 `http://<퍼블릭IP>`를 입력했을 때 준비된 웹페이지가 정상적으로 화면에 뜬다.
- [ ] **또는 방식 B:** 외부 인터넷에서 HTTP 요청 도구로 `GET http://<퍼블릭IP>/health`를 호출했을 때 상태 코드 200과 함께 고정된 응답(예: "OK")이 돌아온다.
- [ ] `README.md` 문서에 자신이 선택한 방식(A 또는 B)과 실제 접속 주소(URL 또는 공인 IP)를 명확하게 기록한다.
- [ ] 외부 접속 결과를 증명하는 스크린샷 화면을 최소 1장 이상 준비한다.

> **주의:** 방식 A와 B를 둘 다 할 필요는 없으며, 하나만 명확히 검증하면 됩니다. 단, 서버 안에서 `localhost`로 접속 성공한 결과만으로는 바깥 인터넷에서 접속된다는 증거가 될 수 없습니다.

## 6. 공식 제출 문서 규격

| 결과물 | 최소 요구 규격 | 쉬운 설명 |
| --- | --- | --- |
| 아키텍처 다이어그램 | `docs/architecture.png` 또는 `.pdf` 1개 | VPC, 서브넷, 인터넷 게이트웨이, 가상 서버, 보안 그룹과 외부 요청 흐름을 시각적으로 나타낸 구조도 |
| 외부 접속 증빙 | `README.md` 기재 + 스크린샷 1장 이상 | 선택한 검증 방식(A 또는 B), 실제 접속 IP/URL 및 정상 응답 화면 캡처 |
| 트러블슈팅 보고서 | `docs/troubleshooting.md` 또는 `.pdf` 1개 | 최소 1건 이상: 문제 증상 → 원인 가설 → 확인 검증 → 조치 내용 → 결과 → 재발 방지 대책 |
| 자원 정리 체크리스트 | `docs/cleanup-checklist.md` 1개 | 실습 종료 후 생성했던 클라우드 자원을 완전히 종료·삭제했다는 구체적 근거 목록 |

> **주의:** 공부하면서 작성하는 번호 순번 문서(`docs/0001-...`, `0002-...`)와 과제 평가에 공식 제출하는 파일은 이름이 다릅니다. 앞으로의 계획서나 단순한 가상 시나리오를 마치 실제 실습을 마친 증빙인 것처럼 제출해서는 안 됩니다.

## 7. 실습 종료 후 자원 정리 (과금 방지)

- [ ] 가상 서버(EC2 인스턴스)가 완전 종료(Terminated) 상태가 되었는지 확인한다.
- [ ] 외장 가상 디스크(EBS 볼륨)가 서버 종료 후 남겨지지 않고 모두 삭제되었는지 확인한다.
- [ ] 고정 공인 IP(Elastic IP)를 할당했다면 연결 해제 후 계정에서 완전 반환(Release)되었는지 확인한다. (만들지 않았다면 미생성으로 기록)
- [ ] 인터넷 출입구(Internet Gateway)의 VPC 연결을 끊고(Detach) 삭제되었는지 확인한다.
- [ ] 서브넷 및 라우팅 테이블 등 연결된 구성 요소를 정리한 뒤 가상 사설망(VPC)이 삭제되었는지 확인한다.
- [ ] 실습 과정에서 추가로 생성한 자원(NAT Gateway, 로드밸런서 ELB/ALB, 데이터베이스 RDS 등)이 있다면 모두 삭제되었는지 확인한다.

> **주의:** 서버를 '중지(Stop)'시키는 것은 '완전 삭제(Terminate)'가 아닙니다. 서버를 중지만 해두어도 가상 하드디스크(EBS) 보관 비용과 고정 IP 비용은 계속 청구될 수 있습니다. AWS 요금 대시보드(Billing Dashboard) 화면은 반영 지연이 발생할 수 있으므로, 당장 화면에 0원이라고 뜬다는 이유만으로 정리가 다 되었다고 단정하지 말고 콘솔의 실제 자원 목록을 직접 확인해야 합니다.

## 8. 권장 사양과 선택 과제 구분

- **권장 최소 사양 가이드:** 프리 티어 무료 대상인 마이크로(micro)급 가상 서버 1대(예: `t2.micro` 또는 `t3.micro`), 널리 쓰이는 리눅스 배포판(Ubuntu LTS 또는 Amazon Linux), 디스크 용량 8~10GiB 수준, 접속 열쇠(키페어) 1개 안전 보관.
- **선택 보너스 1 (HTTPS 암호화 적용):** 도메인을 연결하고 무료 SSL/TLS 인증서(Let’s Encrypt 등)를 적용하여 보안 웹 통신(HTTPS, 443 포트)을 구축합니다.
- **선택 보너스 2 (Docker 컨테이너 배포):** 가상 서버 안에 도커를 설치하고 웹 서비스를 컨테이너로 실행합니다. 서버 내부 `curl http://localhost` 200 검증 및 외부 접속(A/B) 검증을 거친 뒤, `README.md`에 이미지 정보, 포트 매핑, `docker ps` 상태 화면과 외부 접속 화면 등 스크린샷 2장 이상을 첨부합니다.

## 9. 어디까지 확장할 수 있는가? (확장 기준표)

| 변경 및 확장 시도 | 판정 및 해석 | 주의할 점 |
| --- | --- | --- |
| Nginx 기본 환영 페이지 대신 B1-1 웹 포트폴리오 사이트 올리기 | **가능** | 웹 서버가 정상 작동하고 내부·외부 접속 검증 조건을 온전히 만족해야 함 |
| 헬스체크 주소(`/health`) 별도 추가 | **가능** | 상태 점검 응답이 정상적으로 반환되는 경로와 원리를 명확히 설명할 수 있어야 함 |
| 리소스에 관리용 태그를 달거나 로그 기록 남기기 | **가능** | 개인정보나 비밀 키, 암호 같은 민감한 정보는 절대 포함하지 않아야 함 |
| HTTPS 암호화나 Docker 컨테이너 추가 | **선택 과제** | 명시적인 선택 사항이며, 기본 필수 조건인 HTTP(80) 및 SSH(22) 접속 원리를 임의로 생략하지 않아야 함 |
| AWS 대신 GitHub Pages나 Cloudflare만 사용하기 | **불가 (요구사항 불일치)** | 클라우드 가상망(VPC)과 가상 서버(EC2)를 직접 구성해야 하는 필수 요구사항을 대체할 수 없음 |
| EC2 서버 대신 S3 정적 웹 호스팅만 사용하기 | **불가 (요구사항 불일치)** | 가상 서버를 직접 다루는 본 과제의 필수 목적을 대체할 수 없음 |
| SSH 터미널 접속 대신 다른 클라우드 관리 도구만 사용하기 | **실무 대안일 수 있으나 주의** | 실무에서는 다른 도구를 쓸 수 있지만, 본 과제 공식 명세에 명시된 SSH 접속 검증 조건을 만족해야 함 |
| 로드밸런서(ALB), NAT Gateway, 데이터베이스(RDS), 쿠버네티스 추가 | **현재 단계 비추천** | 과제 필수 항목이 아니며, 큰 비용 발생과 불필요한 복잡도로 인해 기본 네트워크 학습을 방해함 |

추가적인 구현이 허용된다고 해서 그것이 지금 당장의 기본기 학습에 반드시 도움이 되는 것은 아닙니다. 필수 기능, 보안 원칙, 비용 통제, 자원 정리 방법을 먼저 완벽히 익히는 것이 우선입니다. 실제 AWS 자원을 생성하거나 변경하는 작업은 항상 학습자의 사전 확인과 승인을 거친 뒤에만 진행합니다.
