## 완성 결과

사용자가 전체 그림 완성을 요청해 공식 Excalidraw MCP로 작성했다. 기존 Excalidraw 탭에 반영하고 전체 장면을 확인했다. 이후 사용자의 피드백에 따라 그림을 간소화했다. AWS 공식 아이콘을 추가하고 오른쪽에 학습 보드를 배치한 뒤, 기존 탭은 전체 보드 맞춤 보기로 두었다. 제출 파일은 캔버스 화면 캡처가 아닌 Excalidraw의 2배 PNG 렌더링 원본이며 3060×2098 픽셀이다. 수정 가능한 제출 원본에는 도형·텍스트·선·아이콘 47개가 개별 요소로 남아 있다. 개인키·암호·MFA·인증 토큰은 포함하지 않았다.

## 공식 아이콘과 옆 학습 보드

- VPC·Public Subnet·Internet Gateway·EC2에 AWS 공식 2026년 7월 아이콘 팩의 SVG를 넣었다. 원래 아이콘 색상은 변경하지 않았다. [공식 출처](https://aws.amazon.com/architecture/icons/), 로컬 원본은 `docs/assets/aws/`에 있다.
- [전체 학습 보드 원본](architecture-learning.excalidraw)과 [전체 보드 PNG](architecture-learning.png)는 왼쪽 아키텍처와 오른쪽 학습 카드 24개를 포함한다. 실습 확인·개념 정리·미완료를 구분하고 상세 근거는 [학습 노트](0036-learning-notes.md)에 기록했다.
- 전체 보드는 7680×5161 PNG이며, 제출용 아키텍처 PNG와 분리해 보관한다. 원본에는 두 프레임을 포함한 편집 요소 148개와 내장 SVG 4개가 있다.
- 이번 환경에서는 MCP 공유 링크로 불러온 SVG가 누락되는 현상을 확인했다. 이미지가 내장된 정규 `.excalidraw` 파일을 기존 캔버스에 직접 불러와 아이콘과 카드의 실제 표시를 확인했다.

## 실제 구성과의 대응

- 서울 리전 `ap-northeast-2` 안에 VPC `b3-1-vpc`, `10.0.0.0/16`을 표시했다.
- Public Subnet `10.0.1.0/24`, `ap-northeast-2a`를 VPC 안에 배치했다.
- IGW는 VPC에 연결되는 인터넷 관문이며 VPC 전체를 포함하는 큰 상자로 표현하지 않았다.
- Route Table은 실습 서브넷에 적용되는 경로 규칙으로 표시했다. `0.0.0.0/0 → IGW`, `10.0.0.0/16 → local`을 구분했고 별도의 통과 서버처럼 연결하지 않았다. 실제 실습은 VPC 기본 테이블의 암시적 서브넷 연결이다.
- Security Group은 EC2 네트워크에 적용되는 점선 경계로 표시하고, 규칙 설명 카드는 VPC와 리전 경계 오른쪽 바깥에 분리했다. 오른쪽 카드는 설명이며 보안 그룹 자원이 VPC 밖에 있다는 뜻이 아니다. 표시 문구는 약어 SG 대신 Security Group으로 풀어 썼다. HTTP 80은 모든 IPv4, SSH 22는 내 IP /32만 허용한다.
- EC2 `b3-1-web`은 Amazon Linux 2023, t3.micro, Nginx이며 검증 당시 퍼블릭 IPv4 `13.125.99.141`을 표시했다. 실제 루트 EBS는 gp3 8 GiB지만 사용자 요청에 따라 그림에서는 생략했다. 실제 볼륨을 삭제한 것은 아니므로 정리 대상에서는 제외하지 않는다.
- 만들지 않은 ALB·NAT Gateway·RDS·다중 EC2를 실제 구성처럼 넣지 않았다. IAM은 요구된 데이터 흐름 구성 요소와 구분하기 위해 이 그림에는 별도의 데이터 통과 지점으로 넣지 않았다.

## 선과 경계 읽는 법

- 파란색: 외부 방문자의 HTTP TCP 80 접속.
- 보라색 점선: 관리자 PC의 관리용 SSH TCP 22 접속. 구현 도구인 로컬 ttyd는 그림에서 생략했다. 접속 출발지는 관리자 PC의 공인 IP이며 AWS 브라우저 접속 서비스를 사용하는 경로가 아니다.
- 초록색 점선: EC2에서 IGW를 통해 외부 인터넷으로 나가는 HTTPS 연결. 실제 아웃바운드 시험의 목적지는 example.com이었지만 고정된 시스템 의존 서비스가 아니므로 그림에는 사이트명을 넣지 않았다. 443은 이 아웃바운드 시험의 목적지 포트이지 443 인바운드를 허용했다는 뜻이 아니다. 그림의 공통 EC2↔IGW 경로와 함께 읽는다.
- 진한 공통 경로: 허용된 TCP 통신과 응답이 지나는 논리적인 공통 경로. IGW가 SG를 대신하는 방화벽이라는 의미는 아니다.
- 주황색 설명선: EC2에 적용되는 Security Group 경계와 오른쪽 규칙 설명을 대응시키는 선이며 인터넷 트래픽 경로가 아니다.

배경색은 공식 AWS 색상 규칙이나 보안 수준을 뜻하지 않는다. 작성자가 파랑=VPC, 초록=Public Subnet, 노랑=Security Group 적용 범위를 쉽게 구분하려고 선택한 보조 표현이다. Route Table과 IGW의 보라색도 인터넷 경로 설정의 연관성을 보여주기 위한 자체 표현이며 공식 AWS 분류 기준이 아니다. 아이콘 자체의 공식 색과 작성자가 선택한 배경·선 색을 구분한다.

요청마다 별도 물리 장비를 순서대로 방문하는 패킷 캡처 그림이 아니라, 구축 자원의 경계·역할·논리적 서비스 흐름을 설명하는 아키텍처다. SG는 독립 서버가 아니고 Route Table 역시 별도 라우터 서버가 아니라 경로 규칙이다.

## 실제 시험과 범위

하단에는 이미 확인한 SSH 로그인, localhost HTTP 200, 외부 브라우저 접속 방식 A, EC2의 외부 HTTPS 200만 기록했다. 외부 페이지는 Nginx 기본 페이지이며 /health를 구현했다고 표시하지 않았다. 브라우저 Instance Connect 접속 성공을 검증한 것으로 쓰지 않았다. 서비스 CIDR 추가안은 최종 SG에 없고 SSH는 개인 IP /32만 유지한다.

VPC·라우팅 구성은 네트워크 구축 기록, EC2·서비스와 통신 결과는 배포 기록, 최종 SG는 `captures/0195-final-security-group-my-ip-only.png`에 근거한다. 비용 무료 보장이나 리소스 삭제 완료를 뜻하지 않는다. 리소스 정리 체크리스트 및 실제 종료·삭제는 아직 별도 작업이다.

## 저장·재편집

- 제출: `docs/architecture.png`.
- 편집: `docs/architecture.excalidraw`를 Excalidraw에서 열거나 기존 탭의 현재 그림을 수정한다.
- 수정 시 원본과 PNG를 함께 갱신한다. 일반 브라우저 편집 내용이 MCP 체크포인트로 자동 반영된다고 가정하지 않는다.
- PNG 자체에 편집 데이터가 포함된다고 보장하지 않으므로 별도 원본을 유지한다.

## 내보내기 검증 기록

이미지 내보내기에서 배경 켜기·다크 모드 끄기·2배 해상도를 선택했다. 작은 미리보기 캔버스는 518×415라 제출 파일로 쓰지 않았다. 이 환경에서 파일 저장·클립보드 동작이 대기 상태에 걸려, 사이트가 실제로 만든 고해상도 PNG Blob을 일시적인 canvas.toBlob 캡처로 읽어 저장했다. 캡처를 위한 원래 메서드는 즉시 복원했으며 내보내기 대화상자를 닫고 기존 캔버스로 돌아왔다. PNG 시그니처와 IHDR의 초기 2640×2116, 간소화 후 3060×2020, 아이콘 추가 후 3060×2098 및 전체 보드 7680×5161 크기를 확인하고 실제 이미지를 열어 겹침·누락을 확인했다.

초기 MCP 작성 체크포인트는 `cd48e77b45284fbbbc`이며, 최종 보관 기준은 정규 Excalidraw JSON으로 저장한 원본 파일이다. 초기 도형은 공식 로컬 MCP의 export_to_excalidraw 링크를 기존 탭에서 열어 적용했다. 이미지와 학습 카드가 포함된 최종 파일은 위의 직접 불러오기 방식으로 적용했다. 새 사용자 작업 탭을 만들지 않았다.
