# B3-1 필수 요구사항과 확장 기준

[과제 요구사항 요약](0051-requirements-and-review-reference.md) · [교육 목표](0004-educational-goals-and-learning-scope.md)

> 흩어진 공식 조건을 재분류한 해석용 문서다. 별도 평가표는 미확인이다. 모든 체크는 미완료로 두며 실습 수행·합격을 주장하지 않는다.

## 1. 계정·리전·비용

- [ ] AWS에서 진행한다.
- [ ] 모든 실습 리소스를 서울 리전 `ap-northeast-2`에 생성한다.
- [ ] 별도 IAM 사용자 또는 Role을 사용한다. 루트로 실습 콘솔에 접근하지 않는다.
- [ ] 프리티어 범위에서 진행할 수 있는지 실제 계정 조건을 확인한다.
- [ ] 실습 종료 후 생성 리소스를 정리한다.

명세의 프리티어 표현은 무료 보장이 아니다. 계정별 적용 조건·크레딧·가격은 실제 생성 시 공식 요금과 계정 화면으로 확인해야 한다. 이 문서에는 현재 가격을 단정하지 않는다.

## 2. 네트워크

- [ ] VPC 1개를 생성한다.
- [ ] Public Subnet 1개를 생성한다.
- [ ] Internet Gateway(IGW)를 VPC에 연결한다.
- [ ] 해당 Subnet의 Route Table에 `0.0.0.0/0 → IGW` 경로가 있다.
- [ ] EC2에서 인터넷 아웃바운드 통신이 된다.

명세의 curl URL 꺾쇠는 설명용 표기와 혼동하지 않는다. 실제 명령은 사용하는 셸에 맞는 URL 인자로 구성한다.

## 3. EC2·웹 서버

- [ ] Public Subnet에 EC2 1대를 생성한다.
- [ ] SSH로 접속할 수 있다.
- [ ] Nginx 등 웹 서버를 설치하고 실행한다.
- [ ] 인스턴스 내부의 `http://localhost`가 HTTP 200을 반환한다.
- [ ] 외부 검증을 위한 퍼블릭 IP와 통신 설정을 갖춘다.

## 4. 보안 그룹과 IAM

- [ ] HTTP 80은 `0.0.0.0/0`에서 접근 가능하다.
- [ ] SSH 22는 본인 IP 또는 지정된 IP 대역에서만 접근 가능하다.
- [ ] 전체 포트 0–65535를 `0.0.0.0/0`에 허용하지 않는다.
- [ ] IAM 권한을 EC2/VPC/SG 실습에 필요한 생성·조회·태그·연결 등의 범위로 제한한다.
- [ ] AdministratorAccess를 부여하지 않는다.
- [ ] 실습과 무관한 S3/RDS 등 서비스 권한을 부여하지 않는다.

SG는 네트워크 접근, IAM은 AWS 관리 작업의 권한이다. 둘은 대체 관계가 아니다.

## 5. 외부 접속 증명 — 하나 선택

- [ ] A: 외부 브라우저에서 `http://<퍼블릭IP>` 페이지 정상 표시.
- [ ] 또는 B: 외부 GET `http://<퍼블릭IP>/health`에 200과 고정 응답 확인.
- [ ] README에 선택한 방식과 URL/IP를 기록한다.
- [ ] 접속 결과 스크린샷을 최소 1장 준비한다.

A/B 둘 다 필수는 아니다. 내부 localhost 성공만으로 외부 접속 성공을 대신하지 않는다.

## 6. 제출 문서

| 결과물 | 최소 요구 |
| --- | --- |
| 아키텍처 | `docs/architecture.png` 또는 `.pdf` 1개. VPC/Subnet/IGW/EC2/SG와 외부 요청 흐름 |
| 접속 증빙 | README의 방식·접속 정보 + 스크린샷 최소 1장 |
| 트러블슈팅 | `docs/troubleshooting.md` 또는 `.pdf`. 최소 1건의 증상 → 가설 → 검증 → 조치 → 결과 → 재발방지 |
| 정리 체크리스트 | `docs/cleanup-checklist.md`. 실제 종료·삭제 근거 |

학습용 번호 문서와 공식 제출 파일은 다르다. 계획서·가상 장애 설명을 실제 수행 증빙으로 제출하지 않는다. 통제 실험이라면 의도한 재현임을 명시하고 평가에서 인정되는지 필요 시 확인한다.

## 7. 정리

- [ ] EC2 Terminated 확인.
- [ ] EBS 볼륨 정리 확인.
- [ ] EIP가 있다면 Release 확인. 없으면 미생성이라고 기록.
- [ ] IGW Detach·삭제 확인.
- [ ] Subnet·사용자 Route Table 등 의존성 정리와 VPC 삭제 확인.
- [ ] 생성했다면 NAT Gateway·ELB/ALB·RDS도 정리 확인.

Billing 확인과 관련 스크린샷은 명세상 권장·선택이다. 비용 표시 지연이 있을 수 있어 즉시 0원이라는 화면만으로 자원 정리를 단정하지 않는다. Stop은 Terminate가 아니고, 서버 중지와 볼륨 삭제는 다르다.

## 8. 권장과 선택 구분

**권장 최소 가이드:** 프리티어 대상 micro 1대, Ubuntu LTS 또는 Amazon Linux, EBS 8~10GiB, 키페어 1개 안전 보관. 구체적 유형의 사용 가능성과 비용은 실습 시 확인한다.

**선택 HTTPS:** 도메인 연결과 인증서 적용.

**선택 Docker:** EC2 내부 컨테이너 실행, 내부 localhost 정상 응답 및 외부 A/B 중 하나 검증. README에 이미지·실행 방식·포트 매핑, docker ps와 외부 접속 스크린샷 최소 2장을 포함한다. 공식 원문의 `http://localhost가`는 오탈자로 보이지만 원문은 보존하고 실제 명령에 그대로 쓰지 않는다.

## 9. 확장은 어디까지 가능한가?

| 변경 | 해석 |
| --- | --- |
| Nginx 기본 페이지 대신 B1-1 포트폴리오 | 가능. 웹 서버와 내·외부 검증 조건 유지 |
| /health 추가 | 가능. 정상 응답의 범위를 명확히 설명 |
| 태그·운영 설명·추가 로그 기록 | 가능. 비밀과 개인정보를 제외 |
| HTTPS 또는 Docker 추가 | 명시적 선택. HTTP 80 등 필수 조건을 임의 제거하지 않음 |
| GitHub Pages/Cloudflare만 사용 | AWS VPC·EC2 필수를 대체하지 못함 |
| S3 정적 호스팅만 사용 | EC2 실습 필수를 대체하지 못함 |
| SSH 대신 다른 관리 수단만 사용 | 현업 대안일 수 있으나 명세의 SSH 접속 조건은 남음 |
| ALB·NAT Gateway·RDS·Kubernetes 추가 | 필수 아님. 비용·정리·학습 복잡도 때문에 현재는 비추천 |

추가 구현이 허용되는 것과 지금 학습에 도움이 되는 것은 다르다. 필수 유지·보안·비용·정리 범위를 먼저 확인한다. 실제 AWS 변경은 승인 후 수행한다.

근거: 공식 명세 §2~§7. 이 문서 작성으로 AWS 자원을 생성하거나 변경하지 않았다.
