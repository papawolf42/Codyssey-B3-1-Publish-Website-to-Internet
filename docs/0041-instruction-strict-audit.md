# instruction.md 엄격 점검: 미완료·증빙 부족·조건 이탈

## 2026-10-19 후속 제출 점검

- **A1 보완:** [정리 체크리스트](cleanup-checklist.md)를 작성했고 ID별 결과·확인일·근거를 연결했다.
- **A2 주요 필수 정리 확인:** EC2 Terminated, 서울 EBS·EIP·ENI 없음, 실습 SG·Subnet·IGW·VPC 및 해당 기본 라우팅·ACL·SG 부재를 확인했다. 기본 VPC는 보존했다. 백업용 AMI·스냅샷·임시 S3 정리도 별도 기록에 있다.
- **B2 보완:** localhost 일반 GET 200 증빙은 후속 확보했다.
- **D1/D2 보완:** 브라우저 SSH 권한 저장/성공 미검증/로컬 SSH 성공을 구분하고 README를 실제 Nginx 기본 페이지·삭제 후 상태에 맞췄다.
- **B1 미확인 유지:** Billing과 Cost Explorer의 현재 예상 비용은 0.00이나 EC2 사용료 미표시 원인·프리 티어 범위 준수·확정 청구액은 확인하지 못했다.
- **C1 이력 유지:** 계정 복구의 root 로그인 기록을 지우거나 root를 쓰지 않았다고 바꾸지 않는다. 현재 관리 역할과 실습 사용자 신원은 별개다.
- HTTPS 보너스는 GET 200·모의 갱신까지 확인했으며 자동 갱신은 보장하지 않는다. Docker는 선택 미수행, Terraform은 로컬 검증만, AMI는 AWS 부팅 복원 미시험이다.
- 학습자 자기 설명·실제 평가 PASS는 아직 별도 확인 대상이다. 아래 A~G는 최초 점검 근거를 보존한 기록이며 ‘파일 없음·정리 전’ 문구를 현재 상태로 읽지 않는다.

## 판정 범위

명세 전체와 프로젝트의 실제 기록·제출 파일을 대조했다. 이 점검에서는 AWS에 로그인하거나 현재 리소스 목록·비용·SSH·웹 접속을 새로 조회하지 않았다. 과거 성공 증거는 당시 수행으로 인정하되, 현재도 서버가 실행 중이거나 모든 설정이 유지된다고 단정하지 않는다. 새 Terraform의 mock 테스트를 실제 AWS 배포 증거로 취급하지 않는다.

**최초 점검 당시 종합: 핵심 네트워크·서버 동작과 필수 제출물 3종은 기록상 갖췄다. 하지만 정리 제출물과 정리 완료 근거가 없고, 비용 조건은 검증 부족, root 금지 조건에는 기록된 이탈이 있다. 아직 명세 전체 충족으로 판정할 수 없다.**

## A. 확실히 남아 있는 필수 작업

### A1. 정리 체크리스트 파일 작성: 미완료

- 명세 §2는 `docs/cleanup-checklist.md`를 필수 제출물로 지정한다.
- 현재 파일 목록과 파일 존재 검사에서 해당 파일이 없다.
- 단순히 파일을 만들고 전부 체크하는 것이 아니라, 실제 자원 ID·상태·확인 시점·근거를 기록해야 한다.
- 이 점검에서 체크리스트를 대신 만들거나 삭제 완료 표시를 하지 않았다.

### A2. 실제 리소스 정리와 완료 확인: 기록상 미완료

명세 §4·§7·§8에 맞춰 다음을 확인하고 근거를 남겨야 한다.

- [ ] 실습 EC2의 **Terminated** 상태. 단순 Stop은 대체되지 않는다.
- [ ] 해당 루트 EBS와 실습 관련 미사용 볼륨 삭제 여부.
- [ ] Elastic IP 할당 여부. 사용했다면 Release, 없었다면 해당 없음의 근거.
- [ ] 실습 IGW Detach 및 삭제.
- [ ] 실습 Subnet·Route Table·Security Group 등 의존 자원과 VPC 삭제.
- [ ] NAT Gateway·ELB/ALB·RDS를 추가로 만들었다면 정리. 이번에 만들지 않은 자원까지 새로 만들거나 무관한 자원을 삭제하라는 뜻은 아니다.
- [ ] 과금 위험 자원이 남았는지 최종 점검. Billing 확인은 명세에서 권장이고, 정리 결과를 기록하는 일 자체는 필수다.

현재 README와 SSH 후속 기록은 리소스 종료·삭제 전이라고 한다. 완료 기록이나 체크리스트는 찾지 못했다. 다만 이 점검에서 현재 AWS 상태를 조회하지 않았으므로, 이를 현재 계정의 실시간 실행 상태로 단정하지 않는다. 개별 네트워크 자원 ID는 기존 기록에 있으므로 자원 추적이 전혀 없었던 것은 아니다.

**현재 Terraform 코드로 기존 수동 자원을 바로 삭제할 수는 없다.** 기존 자원을 state에 가져오지 않았고, 새 작성본에도 실제 apply를 하지 않았다.

근거: [README의 검증·정리 현황](../README.md), [브라우저 SSH 후속 기록](0028-browser-ssh-troubleshooting.md), [IaC 검증 범위](0040-terraform-local-validation.md).

## B. 수행 실패가 아니라 충족 근거가 부족한 항목

### B1. 프리티어 범위 준수 확인: 판정 불가

- 명세 §7은 프리티어 범위 내 진행을 요구한다.
- micro급·8 GiB를 선택한 것만으로 무료 사용이 입증되지는 않는다.
- 기록상 Paid 플랜 전환과 고급 기능 활성화는 진행했다. **Paid 전환 자체를 곧 프리티어 위반이나 실제 사용료 발생으로 단정해서는 안 된다.**
- 반대로 무료 크레딧·무료 사용량·EC2·EBS·공인 IPv4 적용 조건과 해당 기간의 실제 비용을 확인해 프리티어 범위라고 판정한 최종 근거도 없다.
- 과거 크레딧 0과 기존 미납 표시 기록은 있지만, 그 금액이 이번 실습 때문이라고 확인된 것은 아니다.

남은 일: 실습 계정과 해당 기간을 기준으로 무료 적용 조건·실제 사용 내역을 확인하고, 정리 후 남는 과금 위험과 함께 기록한다.

근거: [비용 확인 기록](0012-aws-credits-and-cost-check.md), [플랜 전환 기록](0017-aws-plan-upgrade-walkthrough.md).

### B2. localhost 일반 GET 검증: 후속 완료

**2026-10-19 후속:** 사용자가 `curl -i http://localhost`를 직접 실행했고, HTTP 200 및 HTML 본문을 확인·캡처했다. [GET 증빙](captures/0202-nginx-localhost-get-200.png). 이 항목은 보완 완료이며, 아래 설명은 점검 당시의 증빙 부족 사유다.

- 명세 §4의 예시는 `curl http://localhost` 요청의 200 응답이다.
- 기록에서 확인한 명령은 `curl -I http://localhost`이며, 이는 **HEAD** 요청이다. 응답은 HTTP 200이었다.
- 따라서 HTTP 응답이 없었다고 판정할 수 없다. 다만 일반 GET 요청의 200 결과는 확인된 기록에 없으므로, 명세 문구와 완전히 같은 형태의 증거를 추가하면 해석 여지를 없앨 수 있다.
- EC2 SSH 안에서 다음과 같이 확인할 수 있다. 이 점검에서는 실행하지 않았다.

```bash
curl --fail --silent --show-error --max-time 10 \
  --output /dev/null --write-out 'HTTP %{http_code}\n' http://localhost/
```

이것을 명세가 명시적으로 GET만 요구한 것으로 과장하거나, Nginx 미설치·배포 실패로 분류하지 않는다. 외부 HTTPS의 HEAD 200은 인터넷 아웃바운드 연결 시험 근거로 인정할 수 있다.

근거: [배포 기록의 localhost 시험](0025-ec2-deployment-walkthrough.md), [README 내부 HTTP](../README.md).

## C. '안 한 일'과 별개로 이미 발생한 조건 이탈

### C1. root 미사용: 기록상 지켰다고 말할 수 없음

- 명세 §7은 root를 사용하지 않고 별도 IAM 사용자/Role로만 콘솔에 접근하도록 한다.
- 복구 기록에는 **관리 계정 root 로그인 성공과 다른 계정 root 경로 진입**이 있다.
- 이는 과제의 문구를 문자 그대로 적용하면 충돌하는 이력이다. 앞으로 IAM을 쓴다고 과거 root 사용 사실이 사라지는 것은 아니다.
- 다만 실습 VPC·EC2를 root로 생성했다고 확인된 것은 아니다. root 로그인 계정과 실습 멤버 계정을 구분해야 한다.
- 복구 과정에서 Aside가 기존 접근 경로 확인보다 root 암호 찾기를 먼저 안내한 잘못도 기록돼 있다. 이를 사용자만의 실수로 처리하지 않는다.

남은 일: root를 쓰지 않았다고 허위로 적지 않고, 복구 상황·실제 실습 주체·이후 개선을 설명한다. 평가자가 금지 범위를 계정 복구까지 적용하는지는 확인이 필요하며, 이 점검이 자동 탈락을 확정하는 것은 아니다.

**별개 사실:** `forB3-1`에 AdministratorAccess를 새로 부여한 기록은 없다. 복구에 이미 존재하던 `managed/AccountFullAccessRole`을 사용한 것과 실습 IAM 사용자에게 관리자 정책을 붙이는 것은 다르다.

근거: [로그인 복구 설명 §3·§6](0024-aws-login-recovery-쉬운설명.md), [트러블슈팅 TS-004](troubleshooting.md#ts-004-iam-암호-분실과-계정로그인-경로-혼동으로-인한-실습-접근-복구).

## F. 필수 미완료로 세면 안 되는 항목

- HTTPS·도메인: 보너스이므로 하지 않아도 필수 미달 아님.
- Docker: 보너스이므로 하지 않아도 필수 미달 아님.
- `/health`: A를 선택했으므로 B도 추가로 구현할 의무 없음.
- 브라우저 Instance Connect: 로컬 SSH가 성공했으므로 필수 경로가 아님.
- Terraform 실제 배포: IaC 자체가 명세의 필수 항목이 아님.
- ALB·NAT Gateway·RDS·S3·다중 AZ: 이번 필수 구성에 없음.
- Instance Connect 권한 회수: 사용하지 않는 권한을 줄일지는 검토할 수 있지만, 특정 인스턴스·사용자·리전으로 제한된 해당 권한이 남았다는 사실만으로 명세 위반을 확정할 수 없음.
- known_hosts 경고 해결·호스트 키 별도 대조: 보안상 보완할 사항이지만, 성공한 SSH 인증을 미수행으로 바꾸거나 명세에 없는 추가 제출물로 취급하지 않음.

## G. 학습 목표와 평가 방식의 미확인

명세 §3의 '스스로 설명할 수 있어야 한다'는 목표는 문서·AI 답변을 작성한 사실만으로 완료 판정할 수 없다. VPC/라우팅, SG/IAM, 공개 접속 조건, 문제 해결, 과금·정리 순서를 자기 말로 설명하는 최종 점검은 별도로 필요하다. 별도 제출 문서가 추가로 필수라는 뜻은 아니다.

현재 가용성·SSH 소스 IP·서비스 상태는 새로 확인하지 않았다. 서버를 유지하는 상태에서 제출용 증빙을 보강하려면 확인하면 된다. 정리 후에는 무조건 서버를 다시 만들라는 뜻이 아니다. 명세는 평가 시점까지 서버 유지 의무를 적지 않았으며, 별도 평가표와 실시간 시연 요구는 미확인이다.
