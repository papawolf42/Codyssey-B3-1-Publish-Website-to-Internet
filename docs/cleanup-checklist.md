# B3-1 리소스 정리 체크리스트

상태: **주요 실습 자원 정리 확인 완료. 원본 EC2 Terminated, EBS·EIP·ENI 없음, 실습 SG·Subnet·IGW·VPC 및 해당 기본 라우팅 테이블·ACL·기본 SG 부재를 확인했다. 추가 과금 자원·Billing 최종 확인은 남아 있으며 DNS는 사용자 선택으로 유지한다.**

진행 경위: 처음에는 종료 확인창을 취소하고 [HTTPS 보너스](0043-https-bonus-step-by-step.md)와 선택 백업을 먼저 수행했다. 이후 별도 승인과 사용자 직접 실행으로 아래 실습 자원을 정리했다. 초기 준비 기록과 후속 완료 결과를 구분한다.

실습 리전: 서울 `ap-northeast-2`. 콘솔 조작은 사용자가 직접 하고, Aside는 안내·결과 확인·캡처·기록을 담당한다. 확인되지 않은 항목은 완료 표시하지 않는다. 삭제 대상은 아래 실습 자원으로 한정하며 기본 VPC나 다른 프로젝트 자원을 삭제하지 않는다.

## 3. 실제 정리 결과

### HTTPS 보너스로 추가한 DNS가 있다면 먼저 확인

- [x] 실습용 DNS 레코드 생성 사실과 현재 레코드가 남아 있음을 확인했다.
- [ ] 실습 서버를 삭제하기 전에 해당 이름이 재할당 가능한 기존 IP를 계속 가리키지 않도록 레코드 제거 또는 승인된 목적지 변경을 확인했다.
- 대상 이름·결과·확인 시점: 2026-10-19 사용자가 `kodyssey.kr` 루트 A 레코드에 `13.125.99.141`을 DNS only로 저장했다. 변경 전 레코드는 0개였다. [추가 결과](captures/0205-cloudflare-root-a-record.png). 정리 시 이 실습 레코드의 제거 또는 승인된 목적지 변경이 필요하며, 아직 DNS 정리는 하지 않았다.
- HTTPS 주소는 사용자 선택에 따라 루트 `kodyssey.kr`을 사용할 계획이다. 변경한 루트 DNS는 원래 값으로 복원하거나 승인된 목적지로 바꾸고, 메일·다른 서비스의 레코드와 도메인 등록 자체는 삭제하지 않는다.

2026-10-19 후속: 사용자는 A 레코드를 지금 삭제하지 않고 향후 복원 인스턴스의 새 IP로 변경하기로 했다. 기존 IP의 타인 재할당 위험을 안내했고, DNS 정리는 미완료로 유지한다. 초기 EC2 종료 단계에서는 `ec2:DescribeInstanceAttribute` 조회 거부가 있었지만, 이후 사용자 보완 뒤 종료 방지 비활성과 실제 종료를 확인했다. [권한 보완 경위](0049-cleanup-iam-read-permissions.md)와 후속 결과를 구분한다.

## 4. 추가 보존·정리 판단

- 기존 EC2 키 페어 `b3-1-key`는 별도 자원이다. 삭제 또는 재사용 목적 보존 여부는 사용자 확인 후 기록한다. 지금은 삭제하지 않았다.
- 로컬 개인키 파일은 자동으로 지우거나 내용을 문서·캡처에 넣지 않는다.
- 실습 IAM 사용자·정책, 기존 SSO·조직·공유 자원은 이 문서의 네트워크 삭제 작업과 구분하고 별도 승인 없이 삭제하지 않는다.
- 남아 있는 실습용 정책 권한의 유지·회수도 별도로 검토한다.
