# 0009. AWS Root 사용자와 IAM 사용자의 차이

## 질문

Root와 IAM 사용자는 어떻게 다른가?

## 한 문장으로

**Root 사용자는 AWS 계정 자체의 소유자 신원이고, IAM 사용자나 역할은 계정 안에서 정해진 권한으로 AWS에 접근하는 신원이다.**

| 구분 | Root 사용자 | IAM 사용자 | IAM 역할(Role) |
|---|---|---|---|
| 정체 | AWS 계정을 만들 때 함께 생기는 계정 소유자 신원 | 계정 안에 별도로 만드는 사용자 신원 | 사용자나 AWS 서비스가 필요한 동안 맡는 임시 신원 |
| 권한 | 계정 전반에 매우 넓은 권한이 있으며, 일상 작업에 쓰지 않는 것이 원칙 | 연결된 정책이 허용하는 작업만 가능하도록 제한할 수 있음 | 역할에 연결된 정책 범위 안에서 임시 자격으로 작업 |
| 자격 증명 | 계정 이메일과 암호로 로그인. MFA를 켜고 액세스 키는 만들지 않는 것이 안전함 | 콘솔 암호나 액세스 키 등을 가질 수 있어 장기 자격 증명 관리가 필요함 | 보통 역할을 맡는 시점에 임시 자격 증명이 발급됨 |
| 권장 용도 | 계정 수준의 제한된 관리 작업 | 별도 IAM Identity Center가 없는 학습 환경의 제한된 실습 작업 | 사람·서비스가 임시로 AWS 권한을 사용해야 하는 경우 |

## B3-1에서는

과제는 Root 계정으로 실습하지 말고, 별도로 만든 **IAM 사용자 또는 역할**을 사용하라고 요구한다. 그 권한은 VPC, Subnet, Route Table, Internet Gateway, Security Group, EC2 등 이번 실습에 필요한 작업으로 제한하고 `AdministratorAccess`는 부여하지 않는다.

Root가 아닌 IAM 사용자를 골랐다고 해서 자동으로 안전한 것은 아니다. 그 사용자에게 관리자 권한 정책을 연결하면 여전히 광범위한 작업을 할 수 있다. 중요한 것은 신원 종류만이 아니라, 실제로 부여된 권한의 범위다.

## 혼동하지 않기

- **Root / IAM:** AWS에서 누가 관리 작업을 할 수 있는지에 관한 계정 신원과 권한이다.
- **Security Group:** 서버로 어떤 네트워크 트래픽이 들어오고 나갈 수 있는지를 제어한다. IAM 권한을 대신하지 않는다.
- 예를 들어 Security Group에서 SSH 22번을 허용해도, 그 규칙이 VPC를 생성할 AWS 관리 권한을 주는 것은 아니다.

## 기억할 점

Root는 계정 소유자용으로 안전하게 보관하고, 일상적인 실습은 필요한 권한만 가진 별도 IAM 사용자나 역할로 진행한다. Root와 IAM 모두 MFA와 자격 증명 보호가 중요하다.
