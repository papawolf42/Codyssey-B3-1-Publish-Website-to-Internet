# 0009. AWS Root 사용자와 IAM 사용자의 차이

## 질문

Root와 IAM 사용자는 어떻게 다른가?

## 한 문장으로

**Root 사용자는 AWS 계정 자체의 소유자 신원이고, IAM 사용자나 역할은 계정 안에서 정해진 권한으로 AWS에 접근하는 신원이다.**

| 구분 | Root 사용자 | IAM 사용자 | IAM 역할(Role) |
|---|---|---|---|
| 정체 | AWS 계정을 만들 때 함께 생기는 계정 소유자 신원 | 계정 안에 별도로 만드는 사용자 신원 | 사용자나 AWS 서비스가 필요한 동안 맡는 임시 신원 |
| 권한 | 계정 전반에 매우 넓은 권한이 있으며, 일상 작업에 쓰지 않는 것이 원칙 | 연결된 정책이 허용하는 작업만 가능하도록 제한할 수 있음 | 역할에 연결된 정책 범위 안에서 임시 자격으로 작업 |
| 자격 증명 | 계정 이메일과 암호로 로그인. MFA를 켜고 액세스 키는 만들지 않는 것이 안전함 | 콘솔 암호나 액세스 키 등을 가질 수 있어 장기 자격 증명 관리가 필요함 | 보통 역할을 맡는 시점에 임시 자격 증명이 발급됨 |
| 권장 용도 | 계정 수준의 제한된 관리 작업 | 별도 IAM Identity Center가 없는 학습 환경의 제한된 실습 작업 | 사람·서비스가 임시로 AWS 권한을 사용해야 하는 경우 |

## B3-1에서는

과제는 Root 계정으로 실습하지 말고, 별도로 만든 **IAM 사용자 또는 역할**을 사용하라고 요구한다. 그 권한은 VPC, Subnet, Route Table, Internet Gateway, Security Group, EC2 등 이번 실습에 필요한 작업으로 제한하고 `AdministratorAccess`는 부여하지 않는다.

Root가 아닌 IAM 사용자를 골랐다고 해서 자동으로 안전한 것은 아니다. 그 사용자에게 관리자 권한 정책을 연결하면 여전히 광범위한 작업을 할 수 있다. 중요한 것은 신원 종류만이 아니라, 실제로 부여된 권한의 범위다.

## 혼동하지 않기

- **Root / IAM:** AWS에서 누가 관리 작업을 할 수 있는지에 관한 계정 신원과 권한이다.
- **Security Group:** 서버로 어떤 네트워크 트래픽이 들어오고 나갈 수 있는지를 제어한다. IAM 권한을 대신하지 않는다.
- 예를 들어 Security Group에서 SSH 22번을 허용해도, 그 규칙이 VPC를 생성할 AWS 관리 권한을 주는 것은 아니다.

## 기억할 점

Root는 계정 소유자용으로 안전하게 보관하고, 일상적인 실습은 필요한 권한만 가진 별도 IAM 사용자나 역할로 진행한다. Root와 IAM 모두 MFA와 자격 증명 보호가 중요하다.

## 확인 질문의 의미

확인 질문은 설명을 들은 뒤 이해한 내용을 본인 말로 떠올려 보는 짧은 복습이다. 별도의 제출 요건이나 시험이 아니며, 모르는 용어가 있으면 먼저 그 개념을 다시 설명한다.

앞서 적었던 Security Group과 IAM 비교 질문은 Security Group을 설명하기 전에 나온 질문이므로 지금은 보류한다. 두 개념을 배운 뒤에 다시 확인한다.

## 이어서 나온 질문과 설명

### IAM은 무엇의 약자인가?

**IAM = Identity and Access Management**, 즉 신원과 접근(권한) 관리다. AWS에 접속하는 주체가 누구인지(Identity), 그 주체가 어떤 AWS 관리 작업을 할 수 있는지(Access Management)를 다룬다.

### 무료 AWS 계정 가입에 Root가 필요한가?

AWS 계정을 만들 때는 계정 소유자 신원인 Root가 생긴다. 계정의 처음 설정이나 첫 IAM 사용자·역할을 준비할 때 Root로 로그인해야 할 수 있다. 이것은 과제의 VPC·EC2 실습을 Root로 하라는 뜻은 아니다.

공식 `instruction.md` §7에는 **“루트 계정은 사용하지 않으며, 별도로 생성한 IAM 사용자/Role로만 콘솔에 접근한다”**고 적혀 있다. 따라서 학습 리소스를 만들고 조작할 때는 Root가 아니라 IAM 사용자 또는 역할로 로그인한다. 명세는 계정 최초 설정 예외를 따로 설명하지 않으므로, Root는 계정 가입과 IAM 준비에만 제한하고 이후 과제 실습에서는 사용하지 않는 것으로 구분한다.

### MFA란 무엇인가?

**MFA = Multi-Factor Authentication**, 다중 요소 인증(다중 인증)이다. 암호 하나만 확인하는 대신 서로 다른 종류의 증거를 추가로 요구한다. 예를 들면 암호와 인증 앱의 일회용 코드, 또는 암호와 보안 키를 함께 확인한다. Root 계정 보호에 특히 권장되는 보안 설정이지만, 과제의 필수 제출 항목이라고 명세에 적혀 있는 것은 아니다.

인증 앱의 일회용 코드, 복구 코드, 암호는 채팅이나 문서에 붙여넣지 않는다.

### 자격 증명 보호란?

자격 증명(credential)은 계정이나 서버에 본인임을 증명하는 비밀 정보다. AWS에서는 암호, 액세스 키, 세션 토큰, MFA 복구 코드 등이 해당하고, EC2 접속에서는 SSH 개인 키도 보호해야 한다. 이 정보를 채팅·스크린샷·문서·Git 저장소에 올리지 않고, 안전하게 보관하며, 노출되었다고 의심되면 즉시 폐기하거나 교체한다는 뜻이다.

### “VPC를 만들 권한”은 무슨 뜻인가?

여기서 권한은 개념을 이해했는지를 뜻하지 않는다. AWS 콘솔이나 API에 “VPC 생성” 작업을 요청했을 때 AWS가 그 요청을 허용할지를 정하는 계정 권한이다. 예를 들어 IAM 정책이 VPC 생성 작업을 허용하거나 거부할 수 있다.

VPC 자체의 뜻과 네트워크 구조는 아직 배우지 않았으므로, 지금 이 권한을 설계하거나 설정할 필요는 없다. 먼저 용어와 요청 흐름을 설명하고, 그다음 어떤 작업에 어떤 권한이 필요한지 함께 정한다. 권한을 무작정 넓히거나 `AdministratorAccess`로 우회하지 않는다.

Security Group도 지금 외울 필요는 없다. EC2의 네트워크 출입을 제어하는 규칙으로, 해당 단계에 도달했을 때 예시와 함께 설명한다.

## 학습 진행 방식

새 용어를 먼저 짧고 쉬운 말로 설명하고, 왜 필요한지 확인한 뒤 한 번에 한 단계씩 진행한다. 개념을 설명하기 전에 확인 질문을 던지지 않는다. 확인 질문은 이미 배운 내용을 편하게 되짚는 복습이며, 모르면 설명을 다시 듣고 넘어가면 된다.


## 기존에 만든 AWS 아이디·비밀번호를 찾고 싶다면?

새로 가입하기 전에 기존 계정이 있는지부터 확인한다. **저장된 비밀번호를 확인하는 것**과 **잊은 비밀번호를 재설정하는 것**은 다르다. AWS가 기존 비밀번호를 보여주는 것은 아니며, 저장해 둔 정보가 없다면 재설정한다.

### 1. 먼저 저장된 로그인 정보 확인

사용 중인 브라우저의 비밀번호 관리자나 별도 비밀번호 관리 앱에서 `AWS`, `amazon.com`, `aws.amazon.com`을 검색한다. 저장된 사이트 주소와 사용자 이름을 보고 AWS 계정에 맞는 항목인지 확인한다. 아마존 쇼핑 계정과 AWS 계정은 구분한다. 비밀번호는 본인이 관리자에서 확인하거나 자동완성하며, 채팅·문서·Git에는 옮기지 않는다.

### 2. Root 계정을 찾는 경우

- Root의 로그인 아이디는 **AWS 가입에 사용한 이메일 주소**다.
- 이메일을 모르면 평소 쓰는 메일함에서 AWS 가입 확인·청구·결제 관련 메일을 검색해 단서를 찾는다. 메일 속 링크를 바로 누르기보다 공식 AWS 로그인 화면을 이용한다.
- 이메일은 알지만 암호를 모르면 Root 로그인에서 해당 이메일을 입력하고 비밀번호 재설정(Forgot password) 절차를 진행한다. 이메일 수신 권한이 필요하다.
- 이메일에도 접근할 수 없거나 MFA 기기를 잃었다면 별도 계정 복구 절차가 필요하다. 이 경우 공식 AWS 로그인 도움말·지원 경로를 이용한다. 암호 재설정만으로 MFA가 해제되지는 않는다.

### 3. IAM 사용자를 찾는 경우

IAM 로그인에는 **AWS 계정 ID(12자리) 또는 별칭 + IAM 사용자 이름 + 암호**가 필요하다. Root 이메일을 IAM 사용자 이름 칸에 넣는 방식은 아니다.

- 사용자 이름·계정 ID·로그인 URL을 모르면 계정 관리자에게 확인한다. 본인 소유 계정이라면 Root 또는 다른 권한 있는 관리자 신원으로 IAM 사용자 목록을 확인할 수 있다.
- 암호를 잊었다면 권한 있는 관리자가 해당 IAM 사용자의 콘솔 암호를 재설정한다. IAM 사용자는 일반적으로 Root처럼 이메일로 암호를 복구하지 않는다.
- Root와 IAM 암호는 별개다. Root 암호를 바꿔도 IAM 암호가 함께 바뀌지 않는다.

### 지금 할 한 단계

우선 비밀번호 관리자에서 AWS 저장 항목을 찾아본다. 없다면 가입했을 법한 메일함에서 AWS 메일을 검색한다. 그 결과에 따라 Root 복구인지 IAM 사용자 확인인지 나눠 진행한다. 아직 비밀번호 재설정이나 계정 정보 변경을 실행한 것은 아니다.


## 이메일과 암호를 입력했는데 IAM 사용자 칸이 남는 이유

실제 로그인 화면을 확인하니 `IAM user sign in` 상태였고, 가입 이메일이 `Account ID or alias` 칸에 들어가 있었다. 이 칸은 이메일이 아니라 AWS 계정 ID(12자리) 또는 계정 별칭을 받는다. 별도 `IAM username` 칸에는 계정 안에서 생성한 IAM 사용자 이름을 넣는다.

가입 이메일과 Root 암호로 접속하려면 화면 아래 **Sign in using root user email**을 선택한다. 이후 Root 이메일을 입력하고 다음 단계에서 Root 암호로 인증한다. IAM 사용자 칸에 임의의 이름이나 이메일을 채워 해결하는 문제가 아니다.

화면에는 인증 실패와 필수 입력 오류가 표시되었지만, 로그인 방식부터 맞지 않았으므로 이 오류만으로 Root 암호가 틀렸거나 계정이 없다고 단정할 수 없다. 먼저 Root 로그인 화면에서 확인한다. Root로 초기 계정·IAM 준비를 마친 뒤 과제 실습은 IAM 신원으로 진행한다. 이메일·암호의 실제 값은 학습 기록에 남기지 않는다.
