# SSH 키 페어·파일 형식·OpenSSH·PuTTY 쉬운 설명

[실제 EC2 진행 기록](0025-ec2-deployment-walkthrough.md) · [과제 명세](0051-requirements-and-review-reference.md)

## 1. 지금 화면의 질문은 세 가지다

‘RSA와 PEM 중 무엇이 더 좋아요?’는 서로 다른 종류의 물건을 비교한 질문이다.

- **RSA / ED25519**: 열쇠를 만드는 암호 알고리즘.
- **PEM / PPK**: 개인키를 담아 저장하는 파일 형식.
- **OpenSSH / PuTTY**: 그 열쇠를 사용해 원격 서버에 접속하는 프로그램.

우리는 AWS 콘솔 로그인 암호가 아니라 **EC2 안의 Linux에 SSH로 로그인할 열쇠**를 준비하고 있다. Builder ID·root·IAM 로그인과 SSH 로그인은 다르다.

## 2. SSH부터 이해하자

SSH는 Secure Shell의 약자로, 멀리 있는 컴퓨터에 암호화된 연결을 만들어 명령을 실행하는 통신 규약이다. ‘규약’은 서로 통신하는 약속이라는 뜻이다. 웹 브라우저가 HTTP/HTTPS를 말하듯 SSH 프로그램은 SSH 규약으로 서버와 대화한다.

SSH 접속 후 명령은 원격 EC2에서 실행된다. PowerShell 창을 열었다고 모든 명령이 자동으로 원격 서버에서 실행되는 것은 아니다. 접속 전에는 내 PC, 접속 후 원격 프롬프트에서는 EC2라는 차이가 중요하다.

SSH의 기본 포트는 TCP 22다. 웹 방문자는 HTTP 80으로 웹 서버에 들어오고, 우리는 SSH 22로 서버를 관리한다. 공개해야 할 대상과 용도가 다르므로 SSH는 본인 IP로만 제한한다.

## 3. 공개키와 개인키는 왜 두 개일까?

- **공개키**: 서버에서 접속 자격을 확인하는 데 쓰는 정보. 이름처럼 비밀일 필요는 없다.
- **개인키**: 공개키에 대응하는 비밀 열쇠. 내 PC에만 안전하게 보관한다.

EC2 생성 시 선택한 키 페어의 공개키를 Linux 사용자 계정의 SSH 인증에 사용할 수 있도록 설정한다. SSH 클라이언트는 개인키를 이용해 자신이 올바른 열쇠를 가졌음을 증명한다. **개인키 파일 자체를 서버로 전송하는 방식은 아니다.**

누가 개인키를 얻어도 네트워크와 서버 접근 조건까지 충족해야 접속할 수 있지만, 그렇다고 개인키를 공개해도 된다는 뜻은 아니다. 공개키만 있다고 개인키를 다시 만들어낼 수 없고, AWS에서도 같은 개인키를 다시 다운로드할 수 없다.

분실 시 새 키를 생성하는 것만으로 기존 인스턴스의 열쇠가 자동 교체되지 않는다. 다른 관리 접근 경로로 서버의 허용 키를 바꾸는 등의 복구가 필요할 수 있다. 그래서 지금 안전하게 저장하는 것이 중요하다.

## 4. ‘지원하는 환경’은 OS 이름 하나로 정해지지 않는다

호환성은 최소 네 층을 확인한다.

1. **내 PC의 접속 프로그램과 버전**: 어떤 알고리즘과 개인키 파일 형식을 읽을 수 있는가?
2. **접속 대상 서버의 SSH 프로그램과 보안 설정**: 같은 알고리즘으로 인증·통신할 수 있는가?
3. **AWS EC2 기능의 지원 범위**: 해당 인스턴스 OS용 키 페어로 무엇을 허용하는가?
4. **조직의 보안 정책**: 프로그램이 지원하더라도 특정 알고리즘을 제한하지는 않는가?

따라서 ‘Windows니까 ED25519는 전부 안 된다’도, ‘최신 Linux니까 어떤 낡은 SSH 프로그램으로든 된다’도 틀리다.

### RSA

오랫동안 쓰여 호환성이 넓은 공개키 알고리즘이다. EC2에서 생성하는 RSA 키 페어는 2048비트다. Linux 및 EC2 Windows 인스턴스용으로 선택할 수 있다. RSA가 오래됐다고 현재 모든 RSA 인증이 위험하거나 금지된 것은 아니다.

### ED25519

짧은 키와 빠른 처리라는 특징이 있는 현대적인 공개키 서명 알고리즘이다. EC2 Linux 인스턴스용으로 사용할 수 있다. 최신 OpenSSH와 최신 PuTTY 등에서 지원하지만 구버전 프로그램·특정 보안 정책에 따라 제약이 있을 수 있다.

**중요한 구분: AWS가 EC2 Windows 인스턴스용 키 페어에서 ED25519를 지원하지 않는다는 것은, Windows PC의 최신 OpenSSH로 Linux 서버에 ED25519 인증을 할 수 없다는 뜻이 아니다. ‘내 PC가 Windows’와 ‘원격 EC2가 Windows’는 다르다.**

### 우리 실습의 선택

원격 서버는 Amazon Linux 2023이고 접속 프로그램은 Windows OpenSSH를 사용할 계획이다. RSA와 ED25519 중 RSA 기본값으로 진행해도 적절하다. ED25519가 나빠서 배제한 것이 아니라 실습 경로와 기본 옵션을 단순하게 유지한 것이다. 내 PC의 OpenSSH 설치·버전은 아직 확인하지 않았다.

## 5. PEM과 PPK는 무엇이 다른가?

### .pem

이 AWS 화면에서 .pem은 OpenSSH에서 사용할 개인키 다운로드 선택지다. Windows의 OpenSSH, macOS·Linux의 OpenSSH로 접속할 때 사용할 수 있다.

엄밀히 PEM은 텍스트로 암호 자료를 담는 인코딩/포장 방식이며, 인증서나 공개키에도 쓰인다. 따라서 **세상의 모든 .pem 파일이 SSH 개인키인 것은 아니다.** 지금 내려받는 b3-1-key.pem은 그중 EC2 접속용 개인키라는 뜻이다.

### .ppk

PuTTY Private Key의 약자로 PuTTY 계열이 사용하는 개인키 형식이다. PuTTY에서 키 파일을 지정해 접속할 때 편리하다. Windows 전용 SSH 규약이 따로 생기는 것은 아니며 같은 SSH 연결에 사용하는 다른 파일 형식이다.

### 확장자를 바꾸면 변환될까?

아니다. b3-1-key.pem을 b3-1-key.ppk로 이름만 바꾸면 내부 형식은 그대로다. PuTTYgen에서 개인키를 가져와 적절한 형식으로 저장해야 한다. 변환은 같은 열쇠를 다른 포장에 넣는 것이지 자동으로 새 공개키·개인키를 발급받는 것이 아니다. 변환된 파일도 원본만큼 민감하다. 온라인 변환 사이트에 개인키를 업로드하지 않는다.

### 함께 자주 보이는 파일

- **.pub**: 보통 공개키 파일. 개인키와 구분한다.
- **확장자 없는 id_ed25519 / id_rsa**: OpenSSH에서 쓰는 관례적인 개인키 이름. 확장자가 없다고 열쇠가 아닌 것은 아니다.
- **OpenSSH 자체 개인키 형식**: OpenSSH는 전통적인 PEM 키뿐 아니라 별도 OpenSSH 형식도 지원한다. ‘OpenSSH는 .pem 확장자만 읽는다’로 일반화하면 안 된다.
- **.key**: 키 파일에 흔히 붙이는 일반적인 확장자일 뿐 내부 형식을 보장하지 않는다.
- **.ssh**: 보통 키·설정·서버 지문을 저장하는 디렉터리 이름이지 키의 암호 알고리즘이나 파일 형식이 아니다.

파일 내용을 확인하려고 개인키를 화면에 띄우거나 채팅에 붙일 필요는 없다.

## 6. OpenSSH란?

SSH를 실제로 사용할 수 있게 구현한 오픈소스 도구 모음이다. 하나의 프로그램 이름만 뜻하는 것은 아니다.

- **ssh**: 다른 서버에 접속하는 클라이언트.
- **sshd**: 접속을 받아주는 서버 프로그램.
- **ssh-keygen**: 키 생성과 관련 관리를 하는 도구.
- **ssh-agent**: 개인키 사용을 보조하는 에이전트. 지금 단계에서 필수 설정은 아니다.
- **scp / sftp**: SSH를 활용한 파일 전송 도구.

우리 PC에는 우선 **OpenSSH Client**가 필요하다. PC에서 EC2로 접속하려고 Windows에 OpenSSH Server를 설치하거나 PC의 22번 포트를 외부에 열 필요는 없다.

Windows에는 OpenSSH를 선택 기능으로 설치해 쓸 수 있지만 모든 PC에서 설치·활성화돼 있다고 가정해서는 안 된다. 나중에 `ssh -V`로 실행 여부와 버전을 확인한다. 이 명령은 설치 상태 확인용이며 지금 실행했다고 기록하는 것이 아니다.

### PowerShell·Windows Terminal과는 어떻게 다른가?

- **PowerShell**: 명령을 해석·실행하는 셸.
- **Windows Terminal**: PowerShell 등 여러 셸을 띄우는 터미널 앱.
- **OpenSSH의 ssh.exe**: 그 안에서 실행하는 원격 접속 프로그램.

PowerShell 창에서 ssh를 실행할 수 있지만 PowerShell 자체가 SSH 프로그램인 것은 아니다. VS Code 터미널에서도 해당 실행 환경에 ssh가 설치되어 있으면 같은 방식으로 사용할 수 있다. WSL은 별도의 Linux 환경이라 Windows 쪽 설치·파일 경로와 구분해야 한다.

## 7. PuTTY는 무엇이고 OpenSSH와 어떻게 다른가?

PuTTY는 Windows에서 널리 쓰이는 무료 SSH 클라이언트다. 서버 주소·포트·사용자·키 파일 등을 창에서 설정하고 접속하는 GUI가 친숙한 사람에게 편하다. PuTTY 제품군에는 키 생성·변환용 **PuTTYgen**, 명령행 접속용 **Plink** 같은 도구도 있다.

OpenSSH의 일반적인 사용은 터미널에서 ssh 명령을 입력하는 것이고, PuTTY의 일반적인 사용은 GUI에서 설정을 선택하는 것이다. 하지만 ‘OpenSSH만 명령행, PuTTY는 절대로 명령행 불가’라는 뜻은 아니다.

어느 프로그램을 쓰든 **같은 EC2·같은 SSH 규약·같은 Linux 사용자로 접속**할 수 있다. PuTTY로 들어간다고 서버 OS가 달라지거나 권한이 더 커지는 것이 아니다. 네트워크·키·사용자가 맞으면 두 도구는 같은 서버에 이르는 서로 다른 접속 수단이다.

AWS 안내에 따르면 PuTTY는 이 워크플로에서 PEM 개인키를 그대로 쓰지 않고 PuTTYgen으로 PPK로 변환해 사용한다. 우리는 추가 프로그램·변환 절차를 줄이려고 OpenSSH + .pem으로 진행한다.

## 8. Amazon Linux 2023에서 ‘RSA인데 접속이 안 됨’도 가능한 이유

**키의 종류, 서명 방식, 서버 신원 확인은 서로 다른 문제**다.

AL2023은 오래된 ssh-rsa(SHA-1) 서명을 기본적으로 제한한다. 그렇다고 RSA 사용자 키 자체를 모두 거부하는 것은 아니다. RSA 사용자 키로 인증할 클라이언트는 rsa-sha2-256 또는 rsa-sha2-512를 지원해야 한다. 서버 자신의 신원을 증명하는 호스트 키도 별도이며 AL2023 기본 호스트 키는 ED25519/ECDSA다.

이때 ‘RSA 개인키를 골랐는데 처음 접속 메시지에 ED25519가 나온다’는 상황은 모순이 아닐 수 있다. 사용자 인증 키와 서버 호스트 키를 다른 목적으로 쓰기 때문이다. 첫 접속의 서버 지문 확인은 서버가 맞는지 확인하는 단계이며, 무조건 yes를 누르는 습관 대신 별도 신뢰 경로로 지문을 확인한다.

낡은 클라이언트로 호환 오류가 나면 먼저 최신 클라이언트를 검토한다. 해결을 위해 서버 보안 정책을 무작정 낮추거나 LEGACY 암호 정책을 켜는 것은 기본 대응으로 삼지 않는다.

## 9. 나중에 실제로 접속하면 어떤 모습일까?

명령 예시이며 **지금 실행할 단계가 아니다**. 아직 인스턴스와 퍼블릭 IP가 없다.

`ssh -i "개인키의 실제 경로" ec2-user@실제_퍼블릭_IP`

- ssh: OpenSSH 클라이언트 실행.
- -i: 어떤 개인키 파일로 인증할지 지정.
- ec2-user: 현재 선택한 Amazon Linux AMI의 Linux 사용자. IAM 사용자 forB3-1과 다르다.
- 실제 퍼블릭 IP: EC2에 배정된 접속 주소. 아직 예시 값을 실제 주소처럼 사용하지 않는다.

Ubuntu AMI에서는 기본 사용자 이름이 달라질 수 있다. 파일 형식만 맞춘다고 접속되는 것은 아니다. 서버 실행, 퍼블릭 IP, IGW·라우팅, 보안 그룹의 현재 본인 IP 허용, 올바른 사용자·키, 개인키 파일 접근 권한을 함께 확인해야 한다.

## 10. 개인키 안전 보관 체크

- Git 저장소 밖의 본인 전용 폴더에 저장한다. 팀 공유 폴더·공개 클라우드 링크·채팅에 넣지 않는다.
- Windows 파일 접근 권한을 제한한다. 실제 파일 위치 확인 뒤 필요하면 설정하고, 모두에게 읽기 권한을 주는 방식으로 오류를 우회하지 않는다.
- .gitignore는 보조 장치이며 이미 올라간 비밀을 회수해 주지는 않는다.
- 안전한 암호화 백업을 고려하고, 일반 문서나 캡처로 백업하지 않는다.
- 파일을 잃었다고 같은 개인키를 다시 다운로드하거나 키 페어 이름만 같게 만들어 복구할 수 있다고 생각하지 않는다.
- 키 파일 내용은 Aside가 읽지 않고, 다운로드 성공도 파일 내용 열기 없이 사용자 확인으로 검증한다.

이 원본 캡처는 RSA와 .pem 기본값, ED25519와 .ppk 선택지, 안전한 개인키 저장 경고를 확인하는 자료다. 생성 전 옵션 캡처이지 개인키 파일 보관 완료 증거는 아니다.
