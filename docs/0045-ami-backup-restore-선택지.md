# 현재 EC2를 AMI로 백업하고 재생성하는 선택지

[정리 체크리스트](cleanup-checklist.md) · [HTTPS 실제 작업 기록](0043-https-bonus-step-by-step.md) · [Terraform 작성본](../infra/terraform/README.md)

## 결론

AMI를 만들면 현재 서버의 소프트웨어와 파일을 보존해 Nginx·Certbot·HTTPS 설정을 처음부터 다시 설치하는 부담을 줄일 수 있다. 다만 서버 내부의 백업과 VPC 등 전체 환경 복원은 다르고, AMI를 보관하는 동안 연결된 EBS 스냅샷 저장 비용이 생길 수 있으므로 과제의 완전 정리와도 구분해야 한다.

이 문서는 선택지 설명이다. AMI·스냅샷 생성, 권한 변경, 재부팅, 종료·삭제는 실행하지 않았다.

## 1. 저장되는 것

현재 인스턴스의 EBS 기반 AMI를 만들면 선택한 볼륨의 디스크 상태가 스냅샷으로 보존된다. 이 서버에서는 다음과 같은 데이터가 백업 범위에 들어갈 수 있다.

- Amazon Linux 2023와 설치된 Nginx·Certbot 및 관련 패키지.
- 웹 파일과 Nginx 설정.
- 디스크에 저장된 systemd 설정.
- `/etc/letsencrypt`의 인증서와 개인키·계정 정보·갱신 설정.
- 기타 디스크에 남아 있는 사용자 파일·로그.

현재 실행 중인 프로세스·RAM·네트워크 연결까지 그대로 일시 정지해 저장하는 것은 아니다. PC Downloads에 있는 SSH 개인키는 EC2 디스크 밖이므로 백업되지 않는다.

## 2. 별도로 구성해야 하는 것

AMI는 전체 AWS 계정이나 네트워크의 복제본이 아니다. 재생성할 때 VPC·Subnet·IGW·라우팅·Security Group·키 페어 선택 등은 따로 필요하다. 실제로 무엇을 유지하거나 다시 만들지 결정해야 한다.

새 인스턴스의 ID와 자동 할당 공인 IP도 다시 확인해야 한다. Cloudflare A 레코드는 자동으로 따라 바뀌지 않으므로 새 IP로 직접 변경한다. SSH 호스트 키·접속과 서비스 동작도 다시 검증한다.

인증서와 개인키가 포함되고 같은 도메인을 쓰며 인증서가 유효하다면, 일반적으로 기존 인증서를 사용할 수 있다. 그러나 백업·복원은 유효 기간을 연장하지 않는다. 현재 인증서의 확인된 만료일은 2027-01-17이며, 자동 갱신을 설정하지 않기로 했다는 결정도 그대로 고려해야 한다.

## 3. 보안과 운영 주의

- 현재 서버 이미지에는 TLS 개인키와 ACME 계정 정보 등 민감 데이터가 들어갈 수 있다. **비공개 AMI로 관리하고 공개·공유하지 않는다.** 암호화 상태와 접근 권한도 확인한다.
- AMI 생성 과정에서 재부팅이 발생할 수 있다. 무중단이 보장된다고 생각하고 바로 실행하지 않는다. 재부팅 없이 생성하는 선택은 파일시스템 일관성 위험과 함께 검토한다.
- 생성 요청 직후 원본을 삭제하지 않는다. AMI가 사용 가능한 상태인지와 관련 스냅샷 결과를 확인하고, 가능하다면 비용·자원 수 제한을 고려한 복구 검증이 필요하다.
- 보관 중인 실습 IAM 정책에는 `ec2:CreateImage` 등 이미지 작업이 포함돼 있지 않다. 실제 실행 전 이미지·스냅샷 생성과 삭제에 필요한 최소 권한을 검토해야 한다. AdministratorAccess를 붙여 우회하지 않는다.

## 4. 과제 정리와 비용

EC2를 종료하고 원래 EBS를 삭제해도 AMI가 참조하는 스냅샷이 남으면 저장 비용이 계속될 수 있다. AMI 등록 해제만 했을 때 스냅샷이 모두 자동 삭제됐다고 가정하지 않는다. 등록 해제 시 연결 스냅샷 삭제 옵션 또는 별도 삭제를 사용하고 실제 결과를 확인해야 한다. 다른 AMI가 함께 참조하는 스냅샷 등은 삭제되지 않을 수 있다.

따라서 다음 둘은 동시에 성립하지 않을 수 있다.

- AWS에 복원용 AMI·스냅샷을 계속 보관한다.
- 실습으로 생성한 모든 과금 위험 자원을 정리 완료했다고 제출한다.

백업을 임시로 유지해도 되는지는 평가 범위를 확인하고 보존 사실·비용을 명시해야 한다. AMI를 만들기로 하면 정리 체크리스트에 AMI ID·스냅샷 ID·보존/삭제 상태도 추가한다. 최종 완전 정리 시에는 불필요한 AMI와 연결 스냅샷까지 삭제 확인한다.

## 5. 가능한 진행 흐름

1. 평가 시 실행 중인 서버·복구 시연이 필요한지와 백업 임시 보존 허용 여부 확인.
2. 이미지 보존 범위·민감정보·비용·재부팅·IAM 권한 검토.
3. 사용자 확인 후 비공개 AMI 생성 및 생성 완료 확인.
4. 원본 실습 자원을 정리하고 각각 실제 삭제 증빙 기록. 백업이 남아 있다는 사실을 숨기지 않는다.
5. 필요하면 AMI로 새 인스턴스 생성, 네트워크·DNS 설정, SSH·HTTP·HTTPS 재검증.
6. 평가·실습 종료 후 새 자원과 임시 AMI·스냅샷까지 정리.

## 6. Terraform과 조합할 경우

네트워크·보안 설정은 Terraform, 서버 내부 설치 상태는 AMI로 분담할 수 있다. 현재 Terraform 작성본은 Amazon 공식 AL2023 AMI를 조회하는 코드라서 사용자 AMI를 자동으로 선택하지 않는다. 조합하려면 AMI 입력·검증·배포/삭제 범위를 별도로 수정하고 검증해야 한다. 아직 구현하거나 적용하지 않았다.
