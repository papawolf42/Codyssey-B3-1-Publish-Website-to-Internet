# 제출 문서 정리와 분할 커밋 계획

상태: **사용자 승인 후 실행. 문서 정합성·보안·검증을 먼저 점검하고 아래 순서로 분할 커밋한다. 실제 결과는 [커밋·검증 기록](0052-commit-and-validation-report.md)을 따른다.**

## 1. 목표와 현재 기준

- 현재 브랜치: `study`.
- 시작 시 확인한 HEAD: `0584f24` (`docs: verify public subnet IGW routing and explain network concepts`).
- 기존 수정 파일 5개와 다수의 미추적 학습 문서·캡처·다이어그램·Terraform 파일이 있다.
- 기존 변경을 버리지 않고, 학습 기록과 제출 증빙을 의미 있는 단위로 나눠 커밋한다.
- 모든 변경을 한꺼번에 `git add .`로 넣지 않는다.
- **main 병합·cherry-pick·원격 push·이력 재작성은 이번 실행 범위에 포함하지 않는다.**
- AWS·Cloudflare 설정 변경, 자원 재생성, 백업 복원도 하지 않는다.

## 2. 먼저 확인하고 고칠 사항

### 사실과 시점 정리

- README에 남은 ‘정리 보류’, ‘리소스 정리 전’, ‘현재 보안 그룹’ 등 과거 표현을 당시 동작 증빙과 최종 정리 결과로 구분한다.
- 소개의 B1-1 사이트 배포 표현을 실제 확인한 Nginx 기본 페이지와 맞춘다. 실제 하지 않은 콘텐츠 배포를 완료로 적지 않는다.
- 엄격 점검 문서의 과거 ‘정리 체크리스트 없음’ 판정에 후속 완료 결과를 추가한다. 당시 점검 자체를 없던 일로 만들지 않는다.
- 브라우저 SSH의 권한 저장, 연결 실패/미검증, 로컬 OpenSSH 성공을 구분한다.
- IAM JSON은 적용 당시 사본·제안본·최신 상태를 구분한다. 현재 정책 버전 번호를 관찰한 사실과 전체 JSON을 검증한 사실을 혼동하지 않는다.
- root 복구 이력과 현재 관리 역할 세션을 구분한다. 과거 root 미사용이나 모든 제약 충족을 허위로 선언하지 않는다.
- Billing·Cost Explorer의 현재 예상 표시 0.00과 EC2 사용료 미표시 원인·최종 청구액 미확정을 구분한다.
- HTTPS 완료와 자동 갱신 미보장, AMI 로컬 복호화 검증과 AWS 부팅 복원 미시험을 구분한다.

### 보안과 파일 검증

- 개인키·암호·토큰·서명 URL·실제 Terraform state/tfvars·암호화 백업과 복구키를 커밋하지 않는다.
- 새 텍스트와 캡처의 민감정보 여부를 점검한다. 발견 시 원문 값을 출력하지 않고 해당 파일과 처리 방안만 보고한다.
- 민감정보가 든 캡처는 그대로 넣지 않는다. 가린 사본 사용 또는 제외를 검토하며 원본을 임의로 삭제하지 않는다.
- 기존 이력의 문제를 발견해도 자동으로 이력을 재작성하지 않는다.
- 문서 상대 링크, 캡처·이미지·Excalidraw 자산 참조, JSON 형식과 파일 존재를 검사한다.
- Terraform은 로컬 검증 범위만 확인하며 AWS `apply`·`destroy`는 실행하지 않는다.

## 3. 커밋 후보와 순서

파일별 검토를 마친 뒤 정확한 포함 목록을 확정한다. 아래는 작업 흐름과 의존관계에 따른 후보이며, 파일 수를 맞추려고 불필요하게 쪼개지 않는다.

공유 파일에 여러 주제가 섞인 경우 관련 부분별 스테이징을 검토한다. 관련 캡처·자산·정책 사본은 문서와 함께 묶는다. 보안 또는 의존성 문제로 묶음을 바꿔야 하면 이유를 기록한다.

## 4. 각 커밋의 통과 조건

1. 해당 묶음의 명시적인 파일 목록으로 스테이징한다.
2. staged 파일 목록·통계·텍스트 diff를 확인한다.
3. `git diff --cached --check`와 해당 파일의 링크·JSON·코드 검증을 수행한다.
4. 민감한 실제 값이나 무관한 변경이 섞이지 않았는지 확인한다.
5. 커밋하고 해시·메시지·포함 범위를 기록한다.
6. 실패하면 다음 커밋으로 넘어가지 않고 원인을 처리한다. 이미 만든 커밋을 승인 없이 amend/reset하지 않는다.

## 5. 최종 보고

- 순서별 커밋 해시·메시지·변경 범위를 제시한다.
- 남은 수정/미추적/제외 파일과 제외 이유를 확인한다.
- 현재 비용 예상치와 확정 불가 사항, 복원 시험 미실행 등 한계를 유지한다.
- 학습자가 자기 말로 설명하는 평가는 별도 단계로 남긴다. 문서 작성만으로 PASS 처리하지 않는다.
- `main` 제출본 선별·병합과 push는 별도 계획 및 사용자 확인 후 진행한다.
