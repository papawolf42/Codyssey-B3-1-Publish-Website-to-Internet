## 2. 일상 속 비유와 ASCII 개념도

### ① 일상 속 비유로 보는 관계
* **리전 (Region - 서울)**: 서울특별시라는 도시 전체
* **VPC (Virtual Private Cloud - `10.0.0.0/16`)**: 서울시 안에 확보한 **"거대한 사옥 부지(캠퍼스 전체 대지)"**
* **가용 영역 (AZ - Availability Zone)**: 장애 영향을 분리하도록 설계된 **"서로 떨어진 건물 구역(A구역, B구역, C구역, D구역)"**
* **서브넷 (Subnet - `10.0.1.0/24`)**: A동 건물 안에 구획을 나눈 **"특정 부서 전용 업무 층(구역)"**

### ② ASCII 도식: Region, VPC, AZ, Subnet의 관계

그림의 AZ 상자는 이 VPC가 사용하는 AZ 내 구역을 뜻합니다. AZ 자체가 VPC 소유이거나 VPC 내부에 포함되는 것은 아닙니다. VPC와 AZ는 모두 리전 안에 있으며, 서브넷이 특정 VPC와 특정 AZ에 속합니다. 그림은 마지막 확인 당시 실습 VPC만 표현하며 기존 기본 VPC의 서브넷은 생략했습니다.
```text
[ AWS Region: ap-northeast-2 (Seoul) ]
+-------------------------------------------------------------------------------+
| [ VPC: b3-1-vpc (10.0.0.0/16 - Region-wide Network) ]                        |
|                                                                               |
|   +--[ AZ: ap-northeast-2a (Zone ID: apne2-az1) ]-------------------------+   |
|   |  (Physical Isolated Data Center Cluster)                              |   |
|   |                                                                       |   |
|   |   +--[ Subnet: b3-1-public-subnet (10.0.1.0/24) ]-----------------+  |   |
|   |   |  - Belongs strictly to AZ 'ap-northeast-2a'                   |  |   |
|   |   |  - Total IPs: 256  |  Available for ENI: 251 (5 AWS reserved) |  |   |
|   |   |  - IP Range: 10.0.1.0 ~ 10.0.1.255                            |  |   |
|   |   +---------------------------------------------------------------+  |   |
|   +-----------------------------------------------------------------------+   |
|                                                                               |
|   (Other AZs like 2b, 2c, 2d exist in Region, but no subnets created yet)     |
+-------------------------------------------------------------------------------+
```

## 3. 서브넷 생성 입력란별 상세 해설

### ① VPC 선택: `b3-1-vpc (vpc-062ac6fd0606192ab)`
* **입력 목적**: 이 서브넷이 어떤 가상 네트워크 공간 안에 위치할 것인지 상위 부모 네트워크를 지정합니다.
* **선택 이유**: 기본 제공 VPC가 아닌, 이번 실습을 위해 독립적으로 생성한 전용 VPC(`10.0.0.0/16`)를 선택했습니다.

---

### ② 서브넷 이름(Subnet name): `b3-1-public-subnet`
* **입력 목적**: 사람이 콘솔 목록에서 알아보기 쉽도록 붙이는 이름표(식별용 라벨)입니다.
* **주의할 점**:
  * 이름에 `public`이라는 단어가 들어있다고 해서 **AWS가 자동으로 인터넷 연결(퍼블릭 서브넷)을 만들어 주는 것이 아닙니다.**
  * 이 이름은 접속용 도메인 주소나 IP 주소가 아니며, 순수한 관리용 메모일 뿐입니다.
  * 실제로 퍼블릭 서브넷이 되기 위한 기술적 조건은 아래 4절에서 설명합니다.

---

### ③ 가용 영역(Availability Zone): `ap-northeast-2a` (Zone ID: `apne2-az1`)
* **서브넷과 AZ의 관계**:
  * VPC는 리전 전체를 아우르는 논리적 공간이지만, **서브넷은 반드시 물리적으로 하나의 AZ 안에만 속해야 합니다.** (하나의 서브넷이 여러 AZ에 걸쳐 존재할 수 없음)
* **AZ란 무엇인가?**:
  * 하나의 AZ는 독립된 전원, 냉각 장치, 네트워크를 갖춘 **하나 이상의 물리적 데이터센터 묶음**입니다.
  * 한 데이터센터에 정전이나 화재가 나더라도 다른 AZ에 영향을 주지 않는 **장애 격리 구역(Fault Isolation Zone)**입니다.
* **왜 서울의 4개 AZ 중 `a`를 골랐는가?**:
  * 서울 리전에는 4개의 가용 영역(`a`, `b`, `c`, `d`)이 있습니다.
  * `a` 영역이 다른 영역보다 기술적으로 더 빠르다거나 비용이 저렴하다는 근거는 전혀 없습니다.
  * 이번 실습은 단일 퍼블릭 웹 서버를 띄우는 것이 목표이므로, 4개 AZ를 모두 만들 필요 없이 실습 위치로 `ap-northeast-2a`를 선택한 것입니다.
* **Zone ID(`apne2-az1`)를 함께 기록하는 이유**:
  * AWS는 여러 고객 계정 간에 특정 데이터센터로 자원이 편중되는 것을 막기 위해, 계정마다 문자명(`ap-northeast-2a`)과 실제 물리 데이터센터의 매핑을 다르게 배정할 수 있습니다.
  * 반면 **Zone ID(`apne2-az1`)**는 모든 AWS 계정에서 물리적으로 동일한 데이터센터 구역을 가리키는 절대적인 식별자이므로 정확한 인프라 추적을 위해 함께 확인합니다.

---

### ④ IPv4 서브넷 CIDR 블록: `10.0.1.0/24`

#### 1. IPv4 사설 주소 체계 기초
* IPv4 주소는 점(.) 3개로 구분되는 4개의 숫자 묶음(총 32비트)으로 이루어집니다.
* 각 자리(옥텟)는 `0`부터 `255`까지의 숫자만 들어갈 수 있습니다. (예: `10.0.1.0`)

#### 2. CIDR(사이더) 표기법: `/` 뒤의 숫자의 의미
* `/숫자`는 **"앞에서부터 몇 비트(자리)를 고정된 네트워크 번호로 사용할 것인가"**를 나타내는 접두사 길이(Prefix length)입니다.
* **VPC 대역 (`10.0.0.0/16`)**:
  * 앞의 16비트(`10.0.`)가 고정됩니다.
  * 나머지 뒤 16비트를 자유롭게 사용하여 총 **65,536개**의 IP 주소 공간(`10.0.0.0` ~ `10.0.255.255`)을 갖습니다.
* **서브넷 대역 (`10.0.1.0/24`)**:
  * 앞의 24비트(`10.0.1.`)가 고정됩니다.
  * 나머지 뒤 8비트(0~255)만 변경되어 총 **256개**의 IP 주소 공간(`10.0.1.0` ~ `10.0.1.255`)을 갖습니다.
  * 이 대역은 상위 VPC(`10.0.0.0/16`)의 거대한 주소 범위 안에 완전히 쏙 들어가는 올바른 서브넷 범위입니다.

#### 3. 256개 중 실제 사용 가능한 IP는 왜 251개인가? (AWS 예약 주소 5개)
이번처럼 일반 AWS IPv4 주소를 사용하는 서브넷에서는 **처음 4개 IP**와 **마지막 1개 IP**를 예약합니다. BYOIP 같은 특수 구성은 이 설명의 범위에서 제외합니다.

| IP 주소 | 예약 목적 | 사용 가능 여부 |
| :--- | :--- | :--- |
| `10.0.1.0` | **네트워크 주소** (해당 네트워크 식별용) | 사용 불가 (AWS 예약) |
| `10.0.1.1` | **VPC 라우터 주소** (서브넷 기본 게이트웨이) | 사용 불가 (AWS 예약) |
| `10.0.1.2` | **DNS용 AWS 예약 주소** (실제 기본 VPC DNS 주소는 VPC 기본 CIDR + 2인 `10.0.0.2`) | 사용 불가 (AWS 예약) |
| `10.0.1.3` | **향후 AWS 기능 확장을 위한 예비 주소** | 사용 불가 (AWS 예약) |
| `10.0.1.4` ~ `10.0.1.254` | **사용자 할당 가능 주소 (총 251개)** | **실제 할당 가능** |
| `10.0.1.255` | **네트워크 브로드캐스트 주소** | 사용 불가 (AWS 예약) |

* **중요한 오해 방지**:
  * 사용 가능한 IP가 251개라는 것은 **"가상 네트워크 카드(ENI)에 할당할 수 있는 여유 주소가 251개"**라는 뜻이지, 이번 실습에서 251대나 256대의 EC2 서버를 띄워야 한다는 뜻이 아닙니다.
  * 이번 과제에서는 이 서브넷 안에 웹 서버용 EC2 인스턴스 단 1대만 생성하여 주소를 할당받게 됩니다.

---

* 서브넷 이름을 입력하면 콘솔이 자동으로 `Name` 태그를 생성해 줍니다.

## 4. 진짜 '퍼블릭 서브넷'이 되기 위한 필수 요건

앞서 언급했듯이, 이름표를 `b3-1-public-subnet`으로 지었다고 해서 저절로 인터넷 통신이 열리는 것은 아닙니다. IPv4 퍼블릭 서브넷의 핵심은 **연결된 라우팅 테이블에 IGW로 향하는 직접 경로가 있는 것**입니다. 아래 1~2번은 이를 구성하는 단계이고, 3번은 그 안의 EC2가 실제로 인터넷과 통신하기 위한 별도 조건입니다.

1. **인터넷 게이트웨이 (IGW) 연결**: VPC에 외부 인터넷과 통신할 수 있는 관문인 인터넷 게이트웨이(`igw-xxx`)가 생성되어 VPC에 부착(Attach)되어야 합니다.
2. **서브넷 라우팅 테이블(RT) 규칙 등록**: 이 서브넷에 연결된 라우팅 테이블에 **"외부 인터넷행 트래픽(`0.0.0.0/0`)은 모두 IGW로 보내라"**는 규칙이 등록되어야 합니다.
3. **EC2의 실제 인터넷 통신 조건 (서브넷 분류와는 별도)**:
   * 서브넷 안에 위치할 EC2 인스턴스가 외부와 통신할 수 있는 **공인 IP(Public IP 또는 탄력적 IP)**를 할당받아야 합니다.
   * 필요한 통신이 SG와 NACL에서 허용되어야 합니다. 이번 과제의 SG 인바운드는 HTTP 80 공개, SSH 22 본인 IP 제한입니다. SG는 허용된 통신의 응답을 자동 허용하고, NACL은 응답 방향도 별도로 허용해야 합니다. 서버의 웹 서비스와 OS 방화벽도 정상이어야 합니다.

## 5. 부가 안내: 콘솔 오류와 불필요한 게이트웨이

* **NAT Gateway와 Carrier Gateway 불필요**:
  * 이번 과제는 인스턴스가 공인 IP를 직접 부여받아 인터넷과 직접 소통하는 **퍼블릭 서브넷 과제**입니다.
  * 따라서 사설망용 유료 서비스인 **NAT Gateway**나 5G Wavelength 전용인 **Carrier Gateway**는 전혀 생성하거나 연결할 필요가 없습니다.
* **서브넷 생성 화면의 오류 메시지 (`ec2:DescribeCarrierGateways`)**:
  * 화면 상단에 캐리어 게이트웨이 조회 거부 오류가 나타나는 것은 콘솔 웹페이지가 화면에 다양한 서브넷 옵션을 준비하려다 발생한 **단순 IAM 읽기 권한 누락**입니다.
  * 이 조회 오류만으로 서브넷 생성 실패나 필수 설정 누락을 단정하지 않습니다. 실제 생성 결과는 별도로 확인하고, 필수 작업이 막히면 필요한 최소 조회 권한을 재검토합니다.


## 6. 추가 질문: CIDR은 무슨 약자인가요? 클래스는 무엇인가요?

앞서 채팅으로만 답하고 문서 반영을 빠뜨렸던 질문과 설명을 이 절부터 보완합니다.

### CIDR의 풀네임과 읽는 법

**CIDR = Classless Inter-Domain Routing**입니다. 한국어로는 ‘클래스 없는 도메인 간 라우팅’이라고 하며 보통 **‘사이더’**라고 읽습니다.

- **Classless**: 예전의 고정된 A·B·C 등급에 얽매이지 않는다는 뜻입니다.
- **Inter-Domain Routing**: 네트워크 영역 간에 길을 정하는 라우팅을 뜻합니다. 여기서 domain은 웹사이트 도메인 이름 자체를 가리키는 말이 아닙니다.
- 지금 실습에서는 `주소/접두사 길이`로 주소 범위를 나타내는 방법으로 먼저 이해하면 됩니다. CIDR이라는 개념은 표기법뿐 아니라 주소 할당과 경로 집약도 포함합니다.

### ‘클래스’는 프로그래밍의 클래스인가요?

아닙니다. 여기서는 **예전에 IPv4 주소를 나누던 고정 크기 등급**이라는 뜻입니다.

예전 classful 방식은 IP 주소의 앞부분에 따라 A·B·C 등급을 구분하고 기본 네트워크 크기를 정했습니다.

- **A 클래스**: 기본 네트워크 부분 8비트, 마스크 255.0.0.0
- **B 클래스**: 기본 네트워크 부분 16비트, 마스크 255.255.0.0
- **C 클래스**: 기본 네트워크 부분 24비트, 마스크 255.255.255.0

비유하면 예전에는 상자를 ‘대·중·소’ 정해진 크기로만 구분했습니다. CIDR은 그 등급에 묶이지 않고 `/20`, `/27`처럼 필요한 주소 범위를 정할 수 있게 합니다.

**주의: `/24`라고 모두 C 클래스는 아닙니다.** `10.0.1.0/24`는 예전 A 클래스에 속하던 주소 범위를 작게 나눈 예입니다. 지금 실습에서는 옛 클래스보다 CIDR과 접두사 길이로 설명하는 것이 정확합니다.

## 7. 추가 질문: `/24`를 사이더 또는 마스크라고 부르면 되나요?

정확한 용어를 구분하면 다음과 같습니다.

- **`10.0.1.0/24` 전체**: CIDR 표기이며, 여기서는 주소 범위를 나타내는 CIDR 블록입니다.
- **`24`**: 접두사 길이입니다. IPv4 총 32비트 중 앞의 24비트를 네트워크 부분으로 쓴다는 뜻입니다.
- **`255.255.255.0`**: `/24`와 같은 네트워크 경계를 표현하는 서브넷 마스크입니다.
- **`10.0.1.0`**: 이 블록의 네트워크 주소입니다.

따라서 `/24` 자체의 정확한 이름은 **접두사 길이**입니다. ‘서브넷 마스크를 짧게 표현한 것’이라고 이해해도 되지만, 전체 주소나 숫자 모두를 마스크라고 부르지는 않습니다.

```text
10.0.0.0/16  ↔ 마스크 255.255.0.0
10.0.1.0/24  ↔ 마스크 255.255.255.0

IPv4 숫자 한 칸은 8비트
/16: 10.0.[변경].[변경]  → 앞의 두 칸 고정
/24: 10.0.1.[변경]       → 앞의 세 칸 고정
```

위처럼 칸 단위로 설명할 수 있는 것은 /16, /24가 8의 배수이기 때문입니다. /20처럼 숫자 한 칸의 중간 비트에서 경계가 나뉘는 경우도 있습니다. 접두사 길이는 점으로 구분된 숫자 칸의 개수가 아니라 **비트 수**입니다.

## 8. 추가 질문: 왜 `1`이 들어가고, VPC와 서브넷을 둘 다 설정하나요?

### `10.0.1.0`의 `1`은 꼭 써야 하는 숫자인가요?

아닙니다. **VPC 안의 작은 주소 구역 중 하나를 고른 것**입니다. 이번에 세 번째 칸이 1인 /24 구역을 골랐을 뿐이며, 특별한 AWS 예약 번호나 public 표시가 아닙니다.

```text
VPC 전체: 10.0.0.0/16
 ├─ 10.0.0.0/24  ← 이것도 서브넷 범위로 선택 가능
 ├─ 10.0.1.0/24  ← 이번에 선택한 범위
 ├─ 10.0.2.0/24
 └─ … 10.0.255.0/24
```

`10.0.0.0/24`로 시작해도 됩니다. 다만 같은 VPC에 여러 서브넷을 만들 때 **서브넷끼리 주소 범위가 겹치면 안 됩니다.** VPC 범위 안에 서브넷 범위가 포함되는 것은 정상이고, 서브넷끼리 겹치는 것이 문제입니다. 그림은 가능한 구획 예시이지 이 서브넷들을 전부 생성했다는 뜻이 아닙니다.

### 왜 두 범위를 설정하나요?

- **VPC `10.0.0.0/16`**: ‘우리 네트워크가 사용할 전체 땅은 여기까지’라고 큰 경계를 정합니다.
- **서브넷 `10.0.1.0/24`**: ‘그 땅 중 이 구획을 특정 가용 영역에서 쓰겠다’고 작은 경계를 정합니다.

같은 설정을 중복한 것이 아니라 **전체 부지와 그 안의 작은 구획을 각각 지정한 것**입니다. 이번 서브넷 생성 화면의 ‘IPv4 VPC CIDR 블록’은 앞서 VPC에 설정한 범위이고, ‘IPv4 서브넷 CIDR 블록’에는 그 안에 들어갈 작은 범위를 입력합니다.
